# Spellmark apparel production workflow

WizardOS and Warlock remain canonical. Sweaters and T-shirts use the existing Etsy-first ecommerce sync architecture. This workflow does not change the established single-master print-item execution path.

1. Preserve the owner-approved artwork and composition. Save explicit required placements and sleeve side; a clean front means no front production file. Confirm exact garment, colors and every size from the live catalog.
2. Fit complete visible artwork to the actual approved print area, centered and as large as looks balanced without clipping. Record final physical dimensions after visual fit. The current owner accepts effective source resolution above 100 PPI; PNG metadata or upsampling does not prove source detail. Do not use guessed print areas.
3. Compare main-print-only and main-plus-sleeve costs before recommending production. One standard main print may be included; extra print areas cost more. Left/right labels without a surcharge do not prove a free second placement. Quote the actual complete stack and approved variants, including fees and stated shipping/advertising exclusions. Do not claim net profit or increased salability from the design alone.
4. Run `execute_etsy_draft_only` with owner authorization and commerce draft write mode. It verifies canonical package, compliance, catalog availability, private assets and provisional margin, then creates/updates the Etsy draft, inventory and assigned draft imagery. It cannot configure Printful or publish. Existing active listings remain protected by the Etsy draft writer. Older draft previews are provisional until replaced with matching final mockups.
5. Inspect import using `check_printful_import`. A draft may await import availability or an owner-controlled store action; no automatic publication or alternate bridge is permitted. Missing imports are a dependency, not permission to assign a default front print.
6. After imported identities are available, use `preview_printful_placements` with approved owned asset IDs, supported placement names and explicit geometry for every physical variant. Review the saved preview and combined costs. Apply only the exact owner-approved preview through `apply_printful_placements`. Processing resumes can reuse approval only when the plan is identical.
7. Verify every variant's catalog mapping, exact production files, checksums, dimensions, DPI and combined production costs. File verification is separate from garment appearance. Partial supplier failures remain in review.
8. Inspect saved supplier mockups outside the design editor. If the editor glitches, use owner-supplied saved-preview evidence, record who reviewed it and what it shows, and avoid asserting all-size verification from one image. Record the linkage between final files, placement plan and new mockups; an older cached mockup alone does not certify new sizing. Customer listing mockups must match the final visible art and sleeve side.
9. Review customer listing imagery, description, variants, size chart, fulfillment mappings and final contribution margins. Retain the required disclosure exactly: “Created using a combination of original art direction, digital design, and AI-assisted image-making.” Publication and sample orders remain owner actions unless separately authorized.

## Rollout and review

The draft-only operation returns `DRAFT_CREATED_AWAITING_PLACEMENTS` for physical goods with `productionReady: false`, `printfulMutated: false`, `published: false` and `quoteScope: PROVISIONAL_PREFLIGHT`. This is a staging state, not a fulfillment-ready state. It deliberately does not invoke legacy `execute_draft_product` supplier configuration. Deploy and refresh the MCP tool registry before attempting the new operation against Vulpis. Validate the existing print-item tests as well as apparel draft-only behavior.
